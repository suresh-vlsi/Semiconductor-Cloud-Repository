# Semiconductor-Cloud-Repository
RV32IM 5-stage RISC-V core + INT8 systolic-array accelerator SoC, with a Python golden model,
self-checking tests and an open-source ASIC flow (Yosys / OpenLane, SkyWater 130 nm).

```
rtl/                 Verilog-2001/2012 source: core, regfile, PE, systolic array, accelerator, UART, SoC
testbench/           tb_soc.v (full SoC), tb_accel.v (accelerator), programs/ (generated .S tests)
python/              assembler, golden ISS, program generator, systolic timing model, regression, report parser
synthesis/ openlane/ synthesis_reports/   Yosys + OpenLane configs and report output
simulation_logs/     simulator output (logs, VCDs, regression_summary.md)
documentation/       architecture.md (memory map, pipeline, accelerator spec, verification plan, roadmap)
```

## Quick start
```bash
pip install numpy                 # only dependency for the Python side
make selftest                     # assembler encodings + systolic timing model        (no simulator needed)
make iss                          # all programs on the Python golden model             (no simulator needed)

# with Icarus Verilog (sudo apt install iverilog gtkwave):
make test                         # ISS + RTL regression, writes simulation_logs/regression_summary.md
make sim PROG=hello               # one program on the RTL
make wave PROG=mem_hazard         # + simulation_logs/soc.vcd for GTKWave
make accel_tb                     # 200 random matmuls on the accelerator alone
python3 python/gen_programs.py --n 8 && make ACCEL_N=8 test   # 8x8 array

# with Yosys / OpenLane:
make synth && make report
```

## Test programs (testbench/programs/*.S, regenerated by python/gen_programs.py)
| program | what it checks |
|---|---|
| hello | UART output, string loads, polling loops |
| alu_test | 384 checks: every RV32I ALU op, all RV32M ops incl. div-by-zero / overflow / MULH variants (expected values from independent Python math) |
| mem_hazard | LB/LH/LBU/LHU sign-extension, SB/SH, load-use stall, forwarding, branch flush, JAL/JALR, AUIPC, x0, loops |
| matmul_sw / matmul_accel | 4x4 INT8 matmul in software vs on the accelerator; kernel cycle counts for the speed-up number |

PASS protocol: program writes `1` to SYSCON (0x4000_0000); any other value is a failure code.

## Status — read this
* Python tools (assembler, ISS, program generator, systolic timing model, report parser): **run and passing**.
  The ISS passes all five programs; the systolic schedule is checked against NumPy for N = 2, 4, 8.
* RTL: written to be simulator-clean Verilog and structurally linted, but **has not been simulated yet** —
  no Verilog simulator was available when this was generated. Run `make test`; if something fails, the
  failing program/check number (the failure code) tells you what to look at. Please expect to fix a few small issues.
* Synthesis / OpenLane scripts are provided but untested.

## Not included (natural next steps)
DMA engine, AXI4-Lite fabric (the SoC uses a simple native bus), caches, branch predictor, CSRs/interrupts,
SVA assertions / UVM, FPGA constraints, MNIST firmware. See documentation/architecture.md section 7.
